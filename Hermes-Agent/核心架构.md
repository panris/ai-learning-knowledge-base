# Hermes Agent 核心架构解析

## 系统组件

```
hermes-agent/
├── hermes/           # 核心 Agent 逻辑
│   ├── __init__.py
│   ├── agent.py      # 主 Agent 类
│   ├── memory.py     # 记忆系统（FTS5 + LLM 摘要）
│   ├── skills.py     # 技能系统
│   └── tools/       # 工具集
├── acp_adapter/      # ACP 协议适配（OpenClaw 迁移用）
├── hermes_cli/       # 命令行入口
├── gateway/          # 消息网关（多平台分发）
├── skills/           # 内置技能目录
├── cron/             # 定时任务调度
├── ui-tui/           # 终端 TUI 界面
└── web/              # Web 界面
```

## 记忆系统

### 层级结构

1. **短期记忆**：当次会话上下文
2. **中期记忆**：FTS5 全文索引的会话摘要，支持模糊检索
3. **长期记忆**：Agent 主动持久化的结构化知识

### 检索流程

```
用户查询 → FTS5 全文检索 → LLM 摘要匹配 → 返回相关上下文
```

### 自改进机制

Agent 完成复杂任务后，自动评估是否需要创建新技能：
- 如果某类任务没有对应技能 → 创建 Skill
- 如果技能运行效果不佳 → 优化 Skill 逻辑

## 技能系统（Skills）

技能是 Hermes 的核心扩展机制，每个技能是一个独立目录，包含：

```
skill-name/
├── SKILL.md          # 技能定义（JSON schema）
├── scripts/         # 执行脚本
└── data/           # 运行时数据
```

### 内置技能示例

- `self-improving`：自我反思、自我批评、自动学习
- `coding-agent`：代码任务委派（Codex/Claude Code）
- `session-logs`：会话历史搜索

### 创建自定义技能

通过自然语言描述任务，Agent 可自动生成新技能。

## 网关架构（Gateway）

Gateway 负责消息分发，支持多种平台：

```
用户消息（任意平台）
  → Gateway（统一入口）
  → ACP 协议标准化
  → Agent 处理
  → 原路返回响应
```

支持的平台：
- Telegram
- Discord
- Slack
- WhatsApp
- Signal
- Email（SMTP/IMAP）

## 运行后端

| 后端 | 说明 | 适用场景 |
|------|------|----------|
| local | 直接本地运行 | 开发调试 |
| Docker | 容器化运行 | 一致性部署 |
| SSH | 远程服务器 | 跨机器协作 |
| Daytona | Serverless 容器平台 | 省钱/按需唤醒 |
| Singularity | HPC 容器 | GPU 集群 |
| Modal | Serverless Python | 闲置不收费 |

## ACP 协议

ACP（Agent Communication Protocol）是 Hermes 的内部通信协议：
- 标准化工具调用格式
- 支持跨版本兼容
- 提供 OpenClaw 迁移适配层

## 关键配置文件

- `~/.hermes/hermes-agent/config.yaml` — 主配置
- `~/.hermes/hermes-agent/skills/` — 自定义技能目录
- `~/.hermes/hermes-agent/memory/` — 记忆数据库（FTS5）
